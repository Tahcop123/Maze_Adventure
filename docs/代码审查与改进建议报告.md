# 迷宫游戏代码审查与改进建议报告

> 审查对象：`maze_raylib/`（raylib 5.5 版，16 个 `.c` + 16 个 `.h`，实测 3946 行）
> 审查方式：全量源码逐行审读 + `gcc -Wall -Wextra` 实测编译 + 调用关系交叉验证
> 审查日期：2026-09-10
> 问题统计：**P0 功能缺陷 11 项、P1 性能 6 项、P2 健壮性/质量 12 项、P3 增强 7 项，共 36 项**

---

## 0. 总体结论

渲染层（阶段六：纹理图集 / Bloom / 遮挡剔除）完成度高、可正常编译运行；但**玩法与状态逻辑层存在一批真实功能缺陷，其中 5 项会导致游戏无法被完整通关**，优先级高于《改造总结》第十一节列出的全部渲染增强项。

最需要先处理的事实：

1. 俯视模式正常通关会被旧逻辑直接踢回主菜单，胜利画面不可达；
2. "下一关"按钮不切换状态，第 2、3 关实际玩不到；
3. 胜利画面以 60fps 重复写排行榜文件；
4. 第一人称模式缺少全部格子交互逻辑，无法拾取钥匙、无法通关；
5. 重开关卡时敌人/道具数组从不重置，逐局累积。

以上 5 项均为几行到几十行量级的修改（详见第 1 节与第 5 节路线图）。

## 1. P0：功能缺陷（建议立即修复）

### A1. 俯视模式通关被旧逻辑踢回主菜单，胜利画面永远不可达

- **位置**：`map.c:526-536`（`Judge()`）、调用点 `event.c:73`（`MovePlayer`）、主循环胜利判定 `maze.c:614-623`
- **现象**：持钥匙走到终点时，`MovePlayer` 每步调用的 `Judge()` 先把 `gameState` 置为 `STATE_MENU`；随后主循环 `if (gameState == STATE_MAZE)` 整块跳过，`STATE_WIN` 分支永远没机会执行。玩家看到的是"直接回主菜单"，而非胜利结算。
- **根因**：旧 WinBGIm 版流程（`Judge` 里回菜单）迁移到状态机后未清理，新旧两套胜负裁决并存冲突。
- **修法**：删除 `Judge()` 中"到达终点回 MENU"与"Hp<=0 回 MENU"两个过时分支（主循环已有 GAMEOVER/WIN 判定），胜负统一由主循环裁决；`MovePlayer` 中移除 `Judge()` 调用或让其只保留数据统计。

### A2. "Next Level"按钮不切换状态，第 2、3 关不可达

- **位置**：`maze.c:401-405`、`level.c:10-52`（`StartLevel` 不设置 `gameState`）
- **现象**：点 "Next Level" 调用 `NextLevel()→StartLevel()`，关卡数据被重建，但 `gameState` 仍是 `STATE_WIN`，画面停在胜利页，只能回主菜单；而主菜单 Start Game 永远从第 1 关开始（`StartLevel(0)`），因此第 2、3 关无法进入。
- **附带**：`maze.c:402` 留下空语句 `if (gameState == STATE_MAZE) {}`；`maze.c:618-622` 的 if/else 两个分支完全相同。
- **修法**：按钮回调中 `NextLevel(); gameState = STATE_MAZE;`，并清理上述冗余代码。

### A3. 胜利画面每帧重复插入排行榜并写磁盘

- **位置**：`maze.c:407`（`DrawWin` 内调用 `AddHighScore`）、`save.c:53-72`
- **现象**：`DrawWin()` 是绘制函数、每帧执行；插入排序对后续更小分数使用严格 `>` 比较，同一记录会逐帧向后重复插入，直到榜单被同一条记录填满；并且每帧触发一次 `fwrite(highscores.dat)`（约 60 次/秒）。
- **修法**：进入 `STATE_WIN` 时只记录一次（增加 `scoreLogged` 标志，或在状态切换处统一调用），绘制函数内不得做写盘副作用。

### A4. 第一人称模式缺少全部格子交互，无法通关（比文档自述严重）

- **位置**：`fpview.c:209-219`（`UpdateFPView` 跨格逻辑）、攻击逻辑 `maze.c:483-510`
- **现象**：FP 跨格时只执行了 `step++ / UpdateFog() / Hp--`，**未调用** `Judgekey / CheckCollectibles / CheckItemPickup / CheckTraps / CheckPortals` 及彩色钥匙（编码 6/7/8）拾取。后果连锁：
  - 钥匙无法拾取 → `is_key` 恒为 0 → 到终点不判胜；
  - 金币/宝石/地面道具不收集、陷阱不触发、传送门不传送；
  - FP 转向只改 `fpDirX/fpDirY`，不回写 `playerDir`，空格攻击方向错误。
- **与文档差异**：《改造总结》第十一节仅记录"4 种地面道具未建模渲染"，实际是**逻辑层整体缺失**，FP 当前是无法通关的展示模式。
- **修法**：抽取公共函数 `OnEnterCell(int x, int y)`，把俯视 `MovePlayer` 中的全部拾取/机关/胜负判定收敛进去，FP 跨格时同样调用；FP 攻击方向由 `fpDirX/fpDirY` 反算 `playerDir`。

### A5. 重开关卡时敌人/道具数组从不重置，逐局累积

- **位置**：`enemy.c:7-13`（`InitEnemies`）、`item.c:7-11`（`InitItems`）、`level.c:10-52`（`StartLevel`）
- **证据**：全项目搜索确认 `InitEnemies()`、`InitItems()` **无任何调用点**。
- **现象**：`StartLevel` 不重置 `enemyCount/itemCount`，上一关实体全部残留；反复 F2 重开后计数持续增长，达到 `MAX_ENEMIES/MAX_ITEMS` 上限后 `SpawnEnemy/SpawnItem` 静默失败，新关卡不再刷怪/掉道具。
- **修法**：在 `StartLevel()` 的 `InitMapEntities()` 旁补 `InitEnemies(); InitItems();`。

### A6. 难度选择不生效

- **位置**：`Interface.c:186-211`（只写 `difficulty` 变量）、`level.c:4-8`（固定 `levelConfigs[3]`）
- **现象**：选 Hard 后 Start Game 仍按 `levelConfigs[0]`（Easy 15×20、3 倍 HP、1 敌人）开始；`difficulty` 仅被同样无人调用的 `DifficultyName()` 引用。
- **修法**（二选一）：让 `difficulty` 映射到关卡配置参数；或将该界面改为"关卡选择"，避免摆设功能在演示时被追问。

### A7. 存档只能存不能读，且存档内容残缺、无校验

- **位置**：`save.c:119-165`
- **现象**：
  1. `LoadGame()` 全项目无调用点，暂停菜单只有 "Save Game"，没有读档入口；
  2. 存档未保存：敌人、地面道具、金币、陷阱、传送门、箱子、压力板、冰面、彩色钥匙/门（`keysCollected/doorPositions`）、体力与各增益计时、`Row/Col` 尺寸，即使接上读档，实体也会全部消失；
  3. 所有 `fwrite/fread` 不检查返回值，文件无魔数（magic）与版本号，截断/损坏文件会把半残数据直接读进内存；
  4. 排行榜 `fread` 后不保证 `name` 以 `\0` 结尾，后续 `%s` 显示存在越界风险。
- **修法**：暂停菜单补 "Load Game"；补全字段（或改为存种子+随机状态+实体结构数组）；文件头加 magic+version；逐个校验 IO 返回值与 `currentLevel` 范围；读入后强制补字符串结束符。

### A8. 地图文件格式与新编码体系脱节，且坐标错位

- **位置**：`file.c:12-57`
- **现象**：
  1. `Savefile` 用单字符 `v+'0'` 写出，门（10–12）、金币宝石（20–21）会写成 `':'` 等乱码，`Openfile` 只接受 `'0'-'5'` 与 `'-'`，新元素无法回读；
  2. 保存遍历 `0..Row-1`，而游戏内部坐标是 `1..Row`，整体错位一行；
  3. Open 外部地图后不重置实体/迷雾/尺寸，敌人道具仍停在旧坐标。
- **修法**：改用"数字 + 分隔符 + 行列头"的文本格式；读写统一以 `1..Row / 1..Col` 为准；Open 后走一次与 `StartLevel` 等价的重置流程。

### A9. 第一人称下暂停，鼠标仍被锁死，无法操作暂停菜单

- **位置**：`fpview.c:130`（`DisableCursor`）、`event.c:97-101`（暂停切换）
- **现象**：进入 FP 时锁定隐藏鼠标，按 Esc/P 进入 `STATE_PAUSE` 时没有配对的 `EnableCursor()`，暂停菜单按钮无法点击。
- **修法**：进入 PAUSE 时 `EnableCursor()`，从暂停回到游戏且 `fpMode` 为真时重新 `DisableCursor()`。

### A10. 种子系统空转，同秒内重开得到相同迷宫

- **位置**：`maze.c:12`（`mapSeed` 声明后从未赋值/使用）、`map.c:94`（`srand(time(NULL))`）
- **现象**：《改造总结》宣称有"种子系统"，实际未接线；`time(NULL)` 秒级精度下，1 秒内连续 F2 重开必然得到同一张图，也无法复现/分享种子。
- **修法**：`srand(mapSeed ? mapSeed : (unsigned)time(NULL))`，菜单提供种子输入与显示。

### A11. 15 个成就只实现 8 个判定，7 个永久无法解锁

- **位置**：`save.c:7-23`（成就名表）、`save.c:107-117`（`CheckAchievements`）
- **缺失项**：Pacifist(3)、Bomb Master(5)、Key Master(6)、No Hints(10)、Ghost Buster(12)、Ice Skater(13)、Portal Master(14) 没有任何 `UnlockAchievement` 调用。
- **修法**：在对应事件点（受伤、用炸弹数、集齐彩钥匙、使用提示、击杀幽灵、冰滑次数、传送次数）补埋点统计与判定。

## 3. P2：健壮性与代码质量

### 3.1 编译与构建

- **C1 实测 10 个编译警告，build.bat 未开 `-Wall -Wextra`**。实测清单：
  - `maze.c:565` `DropEnemyLoot` 未用变量 `ex/ey`（2 条）；
  - `map.c:294` 静态函数 `DrawPlayerChar` 定义未使用；`map.c:10-11` `lightTexture/lightTexInited` 未使用；
  - `audio.c:13` `bgmTime` 未使用；
  - `fpview.c:151-152` 两条 `-Wmisleading-indentation`（同行两个 if 误导性缩进）；
  - `linkedlist.c:183/196` `NextNode/NodeObj` 未使用参数 `head`（2 条）。
  - 修法：构建脚本加 `-Wall -Wextra`（建议再加 `-Wshadow -Wconversion` 评估），删除死代码后清零警告。

### 3.2 时序与状态

- **C2 逻辑按帧而非按时间**：陷阱 `cycle++`（map.c:715）、敌人 `moveCounter++`（enemy.c:69）假设恒定 60fps，`SetTargetFPS` 只是请求；掉帧时机关/敌人节奏整体变慢。应累积 `GetFrameTime()` 计时。
- **C5（根因级）全局状态泛滥、状态机缺进入/退出回调**：`inc.h` extern 约 50 个全局变量；11 个状态用裸 switch 分发，没有 onEnter/onExit。A1/A2/A3/A9 这类"进入某状态时的一次性动作无处安放"的缺陷正是该结构的必然产物。建议引入状态进入回调或 `prevState` 变化检测，把一次性逻辑（写榜、锁/放鼠标、停计时）收敛到状态切换点。
- **C8 固定 1280×800，不可缩放/全屏**：Bloom 的 4 张 RT 仅按首次尺寸创建且 `bloomInited` 锁死（fpview.c:107-124），一旦支持改分辨率，后处理不会重建。需要窗口尺寸变化时释放重建 RT。
- **C9 存档/排行榜写工作目录相对路径**（save.c:25-27）：从快捷方式或其他工作目录启动时文件会散落、读不到。建议使用 raylib `SaveStoragePath`。

### 3.3 游戏逻辑一致性

- **C7 敌人 AI 与伤害路径问题**：
  - 幽灵（enemy.c:74-80）穿墙时不识别门、可走入与主区域不连通的区域永久游荡；追击用 `rand()%2` 随机丢一个轴，移动呈斜向抖动；
  - 骷髅撞墙只随机转向一次，可能长期卡角；
  - 玩家受敌存在**两套不一致的伤害路径**：相邻攻击走 `EnemyAttackPlayer`（5–10 伤害、扣盾、1s 冷却，maze.c:541），格子重叠又在 `maze.c:626-640` 直接扣 25 血且"有盾就秒杀敌人"，数值与语义冲突；
  - 击退（maze.c:637）只回退 X 轴且不做 `CanMoveTo` 检查，可能把玩家推进墙格。
- **C4 实体生成多数不检查数组上限**：`SpawnCollectibles/Traps/Portals/Boxes/Plates`（map.c:586 起）均无 `count < MAX_*` 判断，目前仅靠 `levelConfigs` 数量侥幸不越界，改配置即可能溢出。
- **A4 关联**：俯视/FP 两套移动与交互模型并行，状态同步脆弱，修复 A4 时应统一入口。

### 3.4 音频

- **C3**（audio.c）：
  - 全局只有一个 SFX 槽，`PlayKeySound/PlayWinSound` 等连播两个音调时，第二个直接覆盖第一个，"和弦"变单音；建议改为多通道（3–4 槽轮询）；
  - 音频回调 `MyAudioCallback` 内调用 `rand()`（audio.c:39），非实时安全，且 `sfx*` 状态在主线程写、音频线程读，存在数据竞争，应使用 `volatile`/无锁环形缓冲或预生成波形；
  - `bgmEnabled` 无对外开关、无音量调节接口；`InitAudioDevice()` 失败不检查；`UpdateBGM()` 为空函数、`bgmTime` 为死变量。

### 3.5 代码卫生

- **C10**：`SearchNode`（linkedlist.c:78-82）while 循环缺少 `nodeptr = nodeptr->next` 推进，一旦调用即死循环（当前无调用，属潜伏 bug）；`DeleteNode` 摘除的节点未释放（同样未被调用）。无调用死代码：`DrawPlayerChar`、`DrawPeople`（map.c:496）、`DrawSolution`（solution.c:119）、`UpdateBGM`、`DifficultyName`。
- **C6**：HUD 多处 `sprintf` 写入固定小缓冲（maze.c:248/347/377 等），当前数值范围安全但不稳健，建议统一 `snprintf`。
- **C11 帮助文本与真实键位不符**：`Interface.c:143、271-272` 仍写 "X:Edit / E:Generate new map"，实际键位已是 F3 编辑、F2 新地图（阶段四为避开 WASD 冲突改过，文案未同步），汇报演示前建议修正。
- **C12 GPU 资源无释放路径**：FP 的 3 张纹理、`cubeMesh`、`brickMat`、4 张 RenderTexture、2 个 Shader 全程无 `Unload*`，依赖进程退出回收；不支持设备丢失（lost device）与分辨率变更重建。
- 命名与风格：`Creat*`（Create 误拼，沿用旧项目）、`Interface.c` 大写与其余小写文件不统一，可在不影响演示的前提下逐步规范。

## 5. 建议修复路线图

### 第一批：半天内（决定"能否完整通关"，均为几行级修改）

- [ ] A1 删除 `Judge()` 过时分支，胜负统一归主循环
- [ ] A2 Next Level 后补 `gameState = STATE_MAZE`，清理重复分支与空语句
- [ ] A3 胜利记录只执行一次，移除绘制函数中的写盘
- [ ] A5 `StartLevel` 补 `InitEnemies(); InitItems();`
- [ ] A9 FP 暂停/恢复时配对 `EnableCursor/DisableCursor`
- [ ] C1 开 `-Wall -Wextra` 并清零现有 10 个警告
- [ ] C11 同步帮助页键位文案（F2/F3）
